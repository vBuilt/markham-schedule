# Accounts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Public sign-up / sign-in / password reset for markham-schedule, plus a one-line gate for signed-in-and-confirmed features; Refresh now moves behind it.

**Architecture:** A new `internal/auth` package holds password hashing, tokens, rate limiting, the mailer (Resend) and bot check (Turnstile), an account `Service` with the business rules, and its HTTP layer (JSON endpoints, cookie middleware, CSRF, gate). Account rows live in the existing SQLite file via new methods in `internal/store`. New pages are embedded HTML in `internal/web` calling the JSON endpoints, in the style of `status.html`.

**Tech Stack:** Go 1.25, stdlib `net/http`, `modernc.org/sqlite`, `golang.org/x/crypto/argon2` (new dependency), Resend HTTPS API, Cloudflare Turnstile siteverify.

**Spec:** `docs/superpowers/specs/2026-10-30-accounts-design.md`

## Global Constraints

- Nothing that works today without login may start requiring it; every existing test keeps passing unchanged except where a task says so.
- Passwords 10–200 characters; stored only as argon2id hashes; never logged.
- Session, confirm and reset tokens: 32 random bytes, base64url to the client, only SHA-256 stored.
- Session cookie `mds_session`: HttpOnly, SameSite=Lax, Path=/, 30 days sliding (renewed at most once a day); `Secure` only when the request is HTTPS (TLS, or `X-Forwarded-Proto: https` from a trusted proxy).
- Confirm link lasts 24h; reset link 1h; both single-use.
- No account enumeration: sign-up and forgot-password responses identical whether or not the email exists; sign-in failure always `Email or password is incorrect`; emails sent asynchronously.
- Gated endpoints: signed out → `401 {"error":"sign in required"}`; unconfirmed → `403 {"error":"confirm your email first"}`.
- `API_TOKEN` semantics unchanged; it never substitutes for a session.
- Mail from `Markham Drop-In <no-reply@vincentlfilms.com>` by default.
- Schema in the store's `CREATE TABLE IF NOT EXISTS` style.
- Pages: Atkinson Hyperlegible, the palette from `status.html` (light and dark), phone-width friendly, plain sentence-case copy.

## Review Focus

1. **Enumeration through side effects**: sign-up for an existing confirmed address must return the same status/body as for a new one and must not create a session or change the password. (Task 3 tests.)
2. **Token reuse/expiry**: a reset or confirm token used twice, or after expiry, must fail; a used reset token must not leave old sessions alive. (Task 3 tests.)
3. **Spoofed proxy headers from the LAN**: `CF-Connecting-IP` from a non-trusted address must be ignored for rate limiting. (Task 4 test.)
4. **Cross-site POST**: a POST with a foreign `Origin` (or none) to `/api/auth/*` or a gated endpoint must get 403 even with a valid cookie. (Task 4 test.)
5. **Existing clients**: `/`, `/calendar.ics`, `/api/*` GETs and `/status` keep working with no cookie, and with `API_TOKEN` set they still require only the token. (Task 5 test.)

### Task 4: Auth HTTP layer

**Files:**
- Create: `internal/auth/http.go`, `internal/auth/http_test.go`

**Interfaces:**
- Consumes: Task 3 `*Service`.
- Produces:
  ```go
  type HTTPOptions struct { BaseURL string; Trusted []netip.Prefix; TurnstileSiteKey string }
  func (s *Service) Handler(o HTTPOptions) *HTTP
  func (h *HTTP) Middleware(next http.Handler) http.Handler     // reads mds_session, puts user in context; never blocks
  func (h *HTTP) Register(mux *http.ServeMux, wrap func(http.HandlerFunc) http.HandlerFunc) // wrap = api's token check
  func (h *HTTP) RequireConfirmed(next http.HandlerFunc) http.HandlerFunc // 401/403 per Global Constraints; also CSRF for non-GET
  func UserFrom(ctx context.Context) (store.User, bool)
  ```
  Routes (all JSON; POST bodies JSON; all POSTs CSRF-checked):
  `GET /api/auth/me` → `{"user":null,"turnstile_site_key":"…"}` or `{"user":{"email":…,"confirmed":…},…}` (always 200);
  `POST /api/auth/signup {email,password,turnstile}` → 202 `{"status":"check your email"}`;
  `POST /api/auth/confirm {t}`; `POST /api/auth/resend` (signed in);
  `POST /api/auth/signin {email,password}` → 200 + cookie; `POST /api/auth/signout` → 204 + expired cookie;
  `POST /api/auth/forgot {email,turnstile}` → 202; `POST /api/auth/reset {t,password}` → 200 + cookie;
  `POST /api/auth/password {current,new}`; `POST /api/auth/delete {password}` → 204 + expired cookie.
  Errors: `ErrInvalidEmail`/`ErrWeakPassword`/`ErrBadToken` → 400; `ErrBadCredentials`/`ErrWrongPassword` → 401 with fixed messages; `ErrRateLimited` → 429; `ErrBot` → 400 "Couldn't verify you're not a robot."; `ErrBotUnavailable` → 503 "Couldn't check you're not a robot. Try again."; bodies over 16 KiB → 413.
  Client IP: remote addr host; `CF-Connecting-IP` used only if remote addr ∈ `Trusted`. HTTPS: TLS or (`X-Forwarded-Proto: https` from Trusted). CSRF: `Origin` (else `Referer`) host must equal `r.Host` or `BaseURL`'s host.
